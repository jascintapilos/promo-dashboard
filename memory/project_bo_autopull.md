Goal (requested 2026-06-15 by Wai Yip): reduce manual entry into the Weekly Report sheet by pulling promo codes + banners directly from BO APIs. Relates to [[project_weekly_report_dashboard]].

**Script:** `promo-automation/promo-automation/bin/pull-bo-to-sheet.mjs` (note doubled path — repo is the nested `promo-automation/` subdir). Reuses `getAllPromotions` + `getPromotionDetail` (api-client.js), `QP2_BRAND_TO_IDS` (api-mapper-qp2.js), `getSheetsClient` (sheets-client.js — returns a promise → `const {sheets} = await getSheetsClient()`). Args are `--key=value` only (`bin/_args.js` doesn't do `--key value`). Flags: `--from=YYYY-MM-DD --to=YYYY-MM-DD` (default last 7d), `--write` (default dry-run), `--include-test`.

**KEY FINDING:** BO holds ~10× the promos the sheet logs. Window 08–15 Jun: BO returned **234** promos (QPRO1 alone 73; the WCF_VIP*/WCF_FREEBET* World Cup set is fanned across all 17 QPRO + QP2 = ~150 rows) vs the team's curated ~20. So raw dump into the live log is wrong. **Decision: write to a STAGING tab `BO Auto-pull (Promo)`; team reviews & copies wanted rows into `Promo Code Log`.** Dedup keys on `code|||brand` against BOTH live log + staging → idempotent re-runs (verified 0-new on 2nd run). Region derived from `getPromotionDetail().currencies` via MYR→MY/SGD→SG/IDR→ID. TEST_ excluded. promo_type→type via {1 Deposit,2 Cashback,3 Free Credit,4 Free Spin,5 Rebate} (note: sheet's "-Reload" subtype not in BO list row, so Type is coarser than the sheet).

**Coverage (promos):** QPRO (17) + QP2 (4 merchants) + WS1 (5 country BOs: ws1-v3-my/sg/id/th/kh) + WS2. NOT covered = G8, UG/NX. Weekly Report sheet id `1iGOcxKr9S9WFlrHihDfti_RsoUPgazDqnNKAPWMcPkI`.

**WS1/WS2 promo pull** (added 2026-06-15): `igmpPost(siteId, '/PM/GetPromotionsList?pageNum=N&rowPerPage=200', {...})`. GetPromotionsList response row: `{PromotionId, PromotionCode, PromotionName, PromotionType:'Bonus'/'FreeCredit'/'FreeSpin', IsActive, PromotionStartDate:'DD-MM-YYYY'}`. No created_at → use PromotionStartDate as date; no date-window filter (dedup handles idempotency). Multiple WS1 sites with same code → merged into one row with combined regions (e.g. MB8, MY + SG + ID). Requires `igmp-sessions.local.json` — run `node bin/igmp-keepalive.mjs` first; sites with no session are skipped non-fatally. Extra flag: `--skip-igmp` to run QPRO/QP2 only.

**Banner pull** (added 2026-06-15): `bin/pull-bo-banners-to-sheet.mjs`. QPRO+QP2 only (WS1/WS2 banners = BIA/Directus CMS, no API). Uses `getAllBanners(siteId)`. Region from `images[].settings_locale_id` → {1,3}→MY, {6,7}→SG, {8,9}→ID. Date filter on `created_at||start_datetime`. Dedup key: `label|||brand`. Staging tab: `BO Auto-pull (Banner)`, columns: `Start|Brand|Region|Banner Title|End|Status|Pulled at`. Flags: `--from=YYYY-MM-DD --to=YYYY-MM-DD`, `--write`, `--all` (no date filter).

**AUTO-PROMOTE (Option C, 2026-06-15):** `bin/promote-staging.mjs` copies clean staging rows → the reporting tabs the dashboard reads (`BO Auto-pull (Promo)`→`Promo Code Log` drop col H "Pulled at"; `BO Auto-pull (Banner)`→`Banner Log` drop col G). Dedup: promo `code|||brand`, banner `title|||brand|||start`. Junk net `JUNK_RX=/(^|[_\s])(TEST|CANARY|DUMMY|SAMPLE|DEMO|QC|XXX|ABC123)([_\s]|$)/i` on Code/Title — does NOT filter on "Created By" (pull hardcodes 'promo test bot' on every QPRO/QP2 row, lines 98/127, since BO API has no creator field, so it's NOT a junk signal). DRY-run default, `--write` commits. Verified 234 promos promoted, 0 junk, idempotent. Why Option C: Wai Yip rejected manual review ("bound to be human error") — wanted hands-off with junk auto-dropped.
