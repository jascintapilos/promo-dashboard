WS1 and WS2 `PromotionName` values must be **unique** per BO site at save time. Duplicate names create real downstream confusion.

**Why:** The Manual Reward Assignment team assigns rewards to members by selecting the promotion from a drop-down keyed on `PromotionName`, not on `PromotionCode`. If two promos share the same name on the same BO, the assigner can't tell them apart and assigns the wrong one — wrong reward, wrong T&C, wrong rate.

**How to apply:**
- Before any IGMP `--commit` save, probe each target site for existing promos with the candidate `PromotionName`.
- Names today are generated by `api-mapper-igmp.js` as `"<base> (MIN<x> / CAP<y> / TO<z>x)"`. Distinct rate × min-dep × cap × TO combinations naturally diverge, but repeat campaigns of the same shape (e.g. monthly "50% Reload Bonus (MIN500 / CAP888 / TO18x)") collide.
- If a collision is found:
  1. STOP and surface the collision to the operator.
  2. Confirm next move (e.g. append a date suffix `2026-06` / promo_code suffix / campaign tag) — do not silently rename.
- Only applies to **WS1 / WS2 (IGMP)**. QPRO + QP2 are not affected (BO identifies by code, not name).

**Related:**
- [[project-igmp-qc-bundles]] — bundle's `live_state.list_row.PromotionName` is the field the Manual Reward team sees.
- Pre-QC + Sentinel agents should also flag PromotionName collisions when probing live BO state.
