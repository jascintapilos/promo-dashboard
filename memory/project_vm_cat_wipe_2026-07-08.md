**Incident:** On 2026-07-08 10:48–10:53Z, a bulk amend of all `VM_*` promo codes ran as `promo_testbot` in parallel across QPRO1-10/15/16 (12 sites). Context: same-day abuse case in #ops-teamleads (player henry1992, multiple VM claims, shared fingerprint) → Wai Yip 18:28 MYT: "Found the issue. Will amend promo code configurations for all." The amend job's PUT body echoed the detail GET but did not rename `promotion_category` (GET shape) to `promotion_category_turnover` (PUT shape), so **Categories were silently wiped on 414 promos** (413 + 1 that only surfaced on re-sweep). `game_provider_ids`/`target` survived (same name in GET and PUT). See [[put-body-field-renames]] and [[qpro-put-silent-field-wipe]].

**Symptom in BO UI:** Target Amount → Categories AND Game Providers both show "Please Select". Providers were never actually lost — the Edit form only renders the provider selection after categories are selected. Ops (wenwen/alysa/kasturi/simon) had been re-fixing individual codes manually via UI between 07-09 and 07-21 when CS tickets surfaced.

**Restore (2026-07-21):** `tmp/restore-vm-categories.mjs` (adapted from `bin/backfill-categories-bulk.mjs`, plus extra echoes: message_template_sms_id, first_deposit, bypass_turnover, valid_to, reset_day, promotion_ids). All 414 restored to the 7-cat all-games set (installed ∩ SPORT/LIVE CASINO/SLOTS/E-SPORTS/FISHING/CRASH/CRICKET), matching the surviving full-catalog provider lists (44–58 providers). Exception: qpro8 `VM_UNCONTACTABLE_GENERIC` (dummy inbox/popup promo, single PP2 provider) → SLOTS only. Post-PUT drift check on 15 fields + target: 0 drift, 0 failures. FT_VM_* codes were untouched by the 07-08 amend (last updated 06-25).

**Open caveats:**
- 230 of the wiped promos have `blacklist_id=null` — cannot tell if the 07-08 amend wiped it too (no pre-state snapshot); the others kept values 1/2/3/8. Left as-is.
- Whatever the 07-08 amend *intended* to set (abuse controls: e.g. max_per_player=0, daily_max=9999999, recurring=1 observed on VM_DEP1000_GET500_5X) was preserved, not reverted.
- Non-VM promos were not touched by the 07-08 job (its target set was `VM_*` only), so no wider sweep was run.

**How to apply:** Any future bulk amend on QPRO promos MUST use a PUT body builder that maps `promotion_category` → `promotion_category_turnover` (category_id values, not join-row ids) — reuse `bin/backfill-categories-bulk.mjs`'s `buildPutBody` or the canary's `plan.buildUpdate`. After any bulk amend, re-run a cat/gp sweep (`bin/sweep-cat-gp-estate.mjs` or the VM variant) the same day.

**Blacklist template pass (2026-07-21, after operator approval):** all 577 estate targets (VM codes + report promos) verified carrying a blacklist template — 247 linked via `tmp/fix-blacklist-templates.mjs` (per-category-set match through `src/blacklist-template.js`; snapshots per record in `tmp/blacklist-snapshots-*/`; full-field read-back diff, 0 drift). Key platform findings: (1) **template inheritance** — when `blacklist_id` is set, the promo's blacklist is inherited from the template and the per-promo manual rows are locked (BO 422: "Promotion blacklist is inherited from template"); manual rows only apply when FK is null. (2) Per-promo manual rows live in a separate resource: read `POST /api/bo/promotion/blacklistgame` {promotion_id, game_provider_ids, categories}, write `POST /api/bo/promotion/updateblacklistgame` {promotion_id, black_list_sub_categories: rows} where rows = per (provider × currency × category) with sub_categories[{name,status}], status 1 = blacklisted. (3) A promotion PUT with `black_list_sub_categories: []` WIPES manual rows (confirmed by canary before/after) — linking the correct template supersedes/repairs this via inheritance. (4) `promotion_category` join rows are deleted/recreated on every PUT — diff category_id values, not join-row ids. (5) qpro13/qpro14 had no "All games" template — created (both id 6, 72 settings) by porting qpro1's template id 1 mapped by (provider_code, category, sub-cat name) through each site's `/api/bo/blacklist/gameprovider` catalog; create endpoint `POST /api/bo/blacklist` {name, remarks, status, sub_categories:{currency_id:[ids]}}.

All 105 fixed via `tmp/fix-remaining-categories.mjs`: categories derived from name tokens (Slots/LC/Sports only), FS→SLOTS, VIP SPRTS→SPORT, and validated against each promo's SAVED provider list (never modified providers). Dummy/test codes with 1–2 providers → SLOTS; broad junk test codes → all-games 7. qpro4's REL_BASE/BOOSTER lack the "| Slots only" name suffix but are the same 37-provider slots family as qpro1/2/3 → SLOTS. 1 stale report row (qpro2 testCLAUD_reload10v7) deleted from BO. Final state: 517/518 fixed, 0 missing.
